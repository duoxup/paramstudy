# paramstudy Code Review Report

**Date**: 2026-05-11
**Scope**: Full codebase — `src/paramstudy/`, `tests/`, `pyproject.toml`, `examples/`

---

## 1. Architecture & Design

### Layering (excellent)

```
unit.py        → Foundation: unit parsing / representation / serialization
scale.py       → Middle: unit scaling / auto-prefix selection
metadata.py    → Middle: per-column semantic metadata (label, symbol, unit)
spec.py        → Spec: PlotSpec describes *what* to draw
planner.py     → Planner: data → subplot layout plan (pure data, no matplotlib)
render/        → Render: maps the plan onto matplotlib
options.py     → Cross-cutting: all configurable options
api.py         → Entry: user-facing top-level functions
```

### Highlights

- **planner.py is fully decoupled from matplotlib** — it produces pure data structures (`AxesSlot`, `FigurePlan`). This is good separation of concerns and makes the planner independently testable.
- **Frozen dataclasses throughout** — immutability by default for configuration and plan objects.
- **Consistent type hints** with `from __future__ import annotations`.
- **`ColumnMetaRegistry`** supports both JSON and CSV serialization with correct round-trip behavior.
- **`parse_unit`** handles a practical grammar (`ns`, `mm^2`, `mm mrad`, `eV/c`, `W/m^2`) with clean error messages.

### Design observations

1. **Boilerplate in `api.py`**: The six top-level functions (`line`, `scatter`, `heatmap`, `contour`, `tricontour`, `tripcolor`) are nearly identical, varying only in `PlotKind` and how parameters map to `InputMap` / `ResponseMap`. A common `_build_spec_and_draw` factory could reduce code surface area.

2. **`_draw_figures` thin wrapper**: In `api.py`, `_draw_figures` uses `*args: Any, **kwargs: Any` solely to defer the matplotlib import. The type safety loss outweighs the negligible import-time benefit, especially since matplotlib types already appear in the `TYPE_CHECKING` block. Match the signature to `draw_figures` directly.

3. **Duplicate `_resolve_column_scale`**: `matplotlib_axes.py` has one taking `ColumnMetaRegistry | None`; `matplotlib_figure.py` has one taking `ColumnMeta`. The logic is identical. Consolidate.

4. **`InputMap.secondary` semantics vary by plot kind**: For `line` it means `group` (legend); for `scatter`/`heatmap`/`contour` it means the y-axis input. This is documented in docstrings but is a latent source of confusion.

## 2. Potential Bugs

### 2.1 Inconsistent sort logic in `_prepare_heatmap_grid`

**File**: `src/paramstudy/render/matplotlib_axes.py`, lines 416–417

```python
xs = np.sort(df[x_col].dropna().unique())
ys = np.sort(df[y_col].dropna().unique())
```

`_prepare_heatmap_grid` always sorts via `np.sort`, but the internal `groupby` respects `options.data.sort_primary`. When `sort_primary=False`, the groupby order diverges from the returned `xs`/`ys` order. The final `reindex` corrects the alignment, but the behavior does not match user expectations for that option.

Additionally, this function bypasses the module-level `_ordered_values` helper (which preserves first-occurrence order + optional sort), creating an inconsistency with how line/scatter plots handle ordering.

**Severity**: Low (output is correct due to `reindex`, but the option is misleading).

### 2.2 `_clean_csv_unit` silently swallows parse errors

**File**: `src/paramstudy/metadata.py`, lines 229–235

```python
def _clean_csv_unit(value: str) -> UnitLike | None:
    try:
        return parse_unit(value.strip())
    except ValueError:
        return Unitless(label=value.strip())
```

If a user's CSV contains a typo like `"Mev"` instead of `"MeV"`, `parse_unit` raises `ValueError` which is caught and falls back to `Unitless(label="Mev")`. The user gets no error, and subsequent scaling is silently broken.

**Severity**: Medium (data integrity — wrong unit interpretation with no signal).

**Recommendation**: At minimum, emit a `warnings.warn`. Consider a `strict` mode that raises.

### 2.3 `_format_facet_part` silently skips missing columns

**File**: `src/paramstudy/render/matplotlib_figure.py`, line 269

```python
scale = (
    _resolve_column_scale(df, fallback, column_meta, axes_options)
    if fallback in df else None
)
```

If `fallback` (a column name) is not in the DataFrame, unit scaling is silently skipped. This can mask typos in column names passed through facet keys.

**Severity**: Low (only affects title formatting, not data rendering).

### 2.4 `_shared_colorbar_mappable` uses only the first item's colormap

**File**: `src/paramstudy/render/matplotlib_figure.py`, lines 343–359

```python
cmap = getattr(mappable, "cmap", None)
return ScalarMappable(norm=norm, cmap=cmap)
```

`mappable` is `items[0][0]`. In shared colorbar modes, all subplots are expected to use the same colormap, so this is typically correct. However, if a user customizes per-subplot colormaps (unusual but possible), the colorbar would not reflect the full picture.

**Severity**: Low (edge case).

### 2.5 `LogNorm` with `None` limits

**File**: `src/paramstudy/render/matplotlib_axes.py`, lines 438–439

```python
if options.scale.z == "log":
    kwargs["norm"] = LogNorm(vmin=vmin, vmax=vmax)
```

If `vmin` or `vmax` is `None`, some matplotlib versions handle `LogNorm` differently. For safety, fall back to data-derived limits when both are `None` in log mode.

**Severity**: Low (depends on matplotlib version).

## 3. Code Quality

### 3.1 Inconsistent return types for similarly-named helpers

- `planner._ordered_values` → `tuple[Any, ...]` (immutable)
- `matplotlib_axes._ordered_values` → `list[Any]` (mutable)

Different modules, same name, different semantics. Rename one or align the signatures.

### 3.2 Silent default aggregation in heatmap/contour

```python
agg = options.data.agg or "mean"
```

When `AxesDataOptions.agg` is `None` (the default), heatmap and contour plots silently aggregate with `"mean"`. This is reasonable for gridded data but undocumented. Users expecting raw values may be surprised.

### 3.3 `_ordered_values` (matplotlib_axes) silently falls back on sort failure

```python
try:
    return sorted(ordered)
except TypeError:
    return ordered
```

Mixed-type values (e.g., `[1, "a"]`) silently preserve insertion order. Acceptable behaviour but should log a warning.

### 3.4 `_UNSCALABLE_SYMBOLS` is undocumented

```python
_UNSCALABLE_SYMBOLS: frozenset[str] = frozenset({"c"})
```

The speed-of-light symbol `c` is hard-coded as unscalable. This makes physical sense for particle accelerator applications but is not mentioned in the README or docstrings. Users from other domains may be confused when `eV/c` does not auto-scale `c`.

### 3.5 `api.py` lazy import adds no value

```python
def _draw_figures(*args, **kwargs):
    from paramstudy.render.matplotlib_figure import draw_figures
    return draw_figures(*args, **kwargs)
```

Matplotlib types are already referenced in `api.py`'s `TYPE_CHECKING` block, and `__init__.py` eagerly imports pandas-dependent modules. The deferred import saves nothing and costs type safety. Remove the indirection.

## 4. Test Coverage

### Well covered

- All 6 plot kinds: basic drawing at both API and axes level
- Unit parsing (`test_unit.py`): comprehensive, including edge cases
- Unit scaling (`test_scale.py`): simple, compound, pinned, unitless
- Metadata registry (`test_metadata.py`): JSON/CSV round-trip, compact and JSON-style input
- Planner (`test_planner.py`): GRID/FACET modes, ERROR policy, tail slots, page values
- Figure-level: colorbar modes (EACH/FIGURE/ROW/COL), shared color limits, facet title formatting, per-group unit scaling

### Gaps

| Area | Status |
|------|--------|
| `_ordered_values` with mixed-type data causing sort fallback | No test |
| `_clean_csv_unit` fallback to `Unitless` | No test |
| `_prepare_heatmap_grid` with `sort_primary=False` | No test |
| Multi-page rendering (page > 1) | Planner tested, render layer not tested |
| `SecondaryContourOptions` on tricontour / tripcolor | Only heatmap tested |
| `LogNorm` + color limits combination | No test |
| `MissingFacetPolicy.HIDE` and `BLANK` in GRID mode | Only `ERROR` tested |
| `_best_prefix_for_multiplier` in scale.py | Only indirectly via `resolve_compound_scale` |
| Empty DataFrame edge cases in render layer | Planner covered; render layer not covered |

## 5. Configuration & Packaging

**`pyproject.toml`** is clean but minimal:

- `requires-python = ">=3.10"` — correct (uses `|` union syntax)
- Dependencies have **no lower bounds**. `matplotlib>=3.5` should be specified since `layout="constrained"` was introduced in 3.5.
- `py.typed` is correctly configured (PEP 561).
- `ruff` config only sets `line-length=100`. Enabling `pycodestyle`, `pyflakes`, and `isort` rules would catch import ordering and unused variable issues.

---

## 7. Summary

The codebase is well-structured with a clean separation of concerns. The spec → planner → render layering is the right architectural choice and makes the system extensible. The main issues are:

- A few cross-module inconsistencies (sort logic, function signatures)
- Silent fallback paths that can mask user errors (CSV unit parsing, missing columns)
- Gaps in test coverage, particularly around multi-page rendering and edge-case facet policies

No crash-causing or data-corrupting bugs were found. The package is in good shape for a `0.1.0` release. Addressing the high-priority items above would bring it to production-readiness.
